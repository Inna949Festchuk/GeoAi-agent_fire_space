## Тезисы доклада (1,5–2 минуты)

---

### 1. Научное обоснование (25 сек)

**Проблема:**
- Природные пожары — глобальная угроза. Нужно быстро детектировать очаги и оценивать ущерб
- Существующие сервисы дают только точки возгорания, но не оценивают степень поражения

**Наше решение — двухэтапный пайплайн:**

| Этап | Метод | Данные |
|---|---|---|
| **Детекция очагов** | Тепловые аномалии по ИК-каналам (375 м) | NASA FIRMS (MODIS/VIIRS) |

Спутник (сравнение с фоновой температурой: high/medium/low)

↓

Твой фильтр (промышленные зоны из Overture: промышленность / факелы / блики / вулканы)

↓

Реальный природный пожар → на карту

| **Оценка степени выгорания** | Индекс NBR: `(NIR − SWIR) / (NIR + SWIR)` | Sentinel-2, снимки «до» и «после» |

**Ключевая наука:**
- **NBR** (Normalized Burn Ratio) — здоровая растительность отражает в ближнем ИК, выгоревшая — в коротковолновом ИК
- **dNBR** — разница NBR до/после пожара. Классифицируем на 4 степени: не затронуто, слабая, средняя, сильная
- **Cloud masking** — автоматическое исключение облаков через SCL (Scene Classification Layer)
- Точность: 70–85% по валидации (исследования Key & Benson, 2006)

### 2. Архитектура приложения (30 сек)

**Технологический стек:**
```
Frontend (React + MapLibre) ←→ Backend (DRF) ←→ MCP Server
                                    ↓
                              PostgreSQL + PostGIS
```

**Три ключевых компонента:**

1. **Backend (Django REST Framework):**
   - Модели: `FireHotspot`, `BurnArea`, `ProcessingJob`
   - RERST API
   - Геообработка: STAC-клиент для поиска сцен (STAC API — REST-эндпоинт, который принимает поисковые запросы: «дай сцены вот в этом bbox, вот за эти даты, с облачностью не выше X»), расчёт dNBR, векторизация 
   - Фильтрация ложных срабатываний (промышленные объекты, газовые факелы)

2. **MCP Server (FastMCP):**
   - SSE-транспорт для интеграции с внешними AI-агентами (Qwen Code, Claude Code)
   - 6 инструментов - позволяет агентам запрашивать данные и запускать обработку: 

        1. **`search_fires`** — Поиск активных очагов пожаров
        - Ищет термальные аномалии со спутников VIIRS/MODIS
        - Параметры: bbox, источник спутника, период (1-10 дней), минимальная уверенность
        - Возвращает GeoJSON с точками пожаров (координаты, яркость, FRP, время обнаружения)

        2. **`search_sentinel2`** — Поиск сцен Sentinel-2
        - Находит доступные спутниковые сцены для анализа гарей
        - Параметры: bbox, даты начала/конца, максимальная облачность, лимит результатов
        - Возвращает список сцен с датами и процентом облачности

        3. **`get_fire_stats`** — Статистика пожаров
        - Получает агрегированную статистику по пожарам в регионе
        - Параметры: bbox, период (дни)
        - Возвращает: общее количество, разбивку по источникам и уверенности, среднюю яркость и FRP

        4. **`get_burn_stats`** — Статистика гарей
        - Получает статистику по выгоревшим территориям
        - Параметры: bbox
        - Возвращает: общую площадь горения, разбивку по классам тяжести (low/moderate/high)

        5. **`start_fire_detection`** — Запуск детекции пожаров
        - Запускает фоновую задачу загрузки и фильтрации пожаров из NASA FIRMS
        - Параметры: bbox, список источников спутников
        - Возвращает ID задачи для отслеживания прогресса

        6. **`start_burn_mapping`** — Запуск картирования гарей
        - Запускает анализ выгорания по методу dNBR на Sentinel-2
        - Параметры: bbox, дата до пожара, дата после пожара
        - Система автоматически находит ближайшие доступные сцены
        - Возвращает ID задачи для отслеживания прогресса


3. **Геоагент (AI-чат с function calling):**
   - LLM понимает естественный язык: «Покажи гари в районе Байкала за май-август 2024»
   - Вызывает инструменты, получает результаты, автоматически отображает на карте
   - Генерирует аналитические отчёты с диаграммами и экспортом в GeoJSON/CSV

---

### 3. Что реализовано (20 сек)

| Этап | Результат |
|---|---|
| **Обнаружение пожаров** | Загрузка из NASA FIRMS, отсев ложных срабатываний, PostGIS, REST API с GeoJSON |
| **Картирование гарей** | NBR/dNBR по Sentinel-2, полигоны в БД, визуализация, cloud masking через SCL |
| **AI интеграция** | Чат с function calling, MCP для внешних агентов, генерация отчётов |
| **Умная фильтрация** | Overture Maps: spatial join с промзонами, динамическое обновление кэша |
| **Аналитические отчёты** | Структурированные отчёты, severity distribution, экспорт в GeoJSON/CSV |
| **Документация** | Swagger на `/api/docs/`, management commands, научное обоснование |

### 4. Практический показ (30–45 сек)

**Демо-сценарий:**

1. **Открываем приложение** → видим интерактивную карту

2. **Пишем в чат запрос:**
   > «Сгенерируй аналитический отчёт по гарям в районе Иркутской области и озера Байкал за май 2024 — август 2024 года»

3. **Что происходит:**
   - AI понимает запрос, вызывает инструмент `start_burn_mapping`
   - Система ищет сцены Sentinel-2, считает NBR/dNBR, векторизует полигоны
   - Результаты появляются на карте с цветовой кодировкой по степеням

4. **Получаем аналитический отчёт:**
   - Суммарная площадь гари в гектарах
   - Распределение по четырём степеням поражения (диаграмма)
   - Кнопки экспорта: GeoJSON и CSV

5. **Показываем API (опционально):**
   ```
   GET /api/reports/{id}/
   GET /api/burns/?bbox=107.5,52,109,54
   ```

**Итог:**
> «Мы объединили научные методы ДЗЗ, геопространственную обработку и AI-агентов в единый сервис, который отвечает на вопрос: сколько сгорело и с какой степенью поражения.»
